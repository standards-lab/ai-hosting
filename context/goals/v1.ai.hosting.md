## Task brief · upgrades

**Problem**

ai-hosting has no repeatable way to evaluate a vLLM release, a row's settings, or a replacement
model. spike-hosting-upgrades proved a convention, but on llama.cpp. The agent and vision rows rest
on v0.33.0 measurements under a v0.34.0 pin, and nothing lists such rows; the bench has no agent
scenario; and the cell rule exists only as a hand loop. v1.harness's plugin and
`model-evaluation` build on this convention.

**Behaviors**
1. ai-hosting's docs hold three new kinds of document:
   - **The convention:** when survey runs, what triggers a measure, the record an adoption
     leaves, and what stays with `model-evaluation`.
   - **The policy:**
     - Origin: no model of Chinese origin, and a fine-tune takes its base's origin. The rule is
       read at three levels: the weights and their base chain, any distillation teacher, and
       each encoder, projector, or tokenizer in the inference path.
     - Artifact integrity: safetensors, and repository code only from an accepted list.
     - The quantization floor for vLLM's checkpoint formats.
     - The tuning rule: accuracy first, then the throughput peak. Agent keeps its ITL floor of
       100 ms or less at its load target.
   - **A descriptor for each of the four hosts:** the SSH short name, the alias the host serves,
     a link to that row's load target in its class profile (never restated), run noise where it
     has been measured, and watch items.
2. Survey flags a host descriptor that restates a figure the profile holds as stale, under
   proposed changes.
3. Survey on one host reads, without root:
   - the host's probe: pending updates, debt, failed units, and the running rows;
   - `mise run currency`: the vLLM release, image tags, and digests;
   - `mise run watch`: upstream entries;
   - each row's flags, reviewed against the release notes since its `measured_vllm`;
   - model candidates for each role, gated by the policy.

   It writes a dated report into the untracked state directory, one per host per run, with a
   verdict on each item: verify, take, hold, or skip. It reads sources fresh, with no cache, and
   changes nothing on the host or in committed documents; changes are proposals in its report.
4. The watch register gains an entry for a gfx1151 MIOpen find database in vLLM's ROCm image.
   The entry's action is to drop the audio image's FAST setting. The spike's blocker register is
   not carried over; the watch register holds its role.
5. `hosting profile stale` lists, read-only, each row whose `measured_vllm` is older than the vLLM
   pin, by class and alias, and exits 0 either way. Today it lists agent and vision.
6. A bench cell runner runs one scenario on one row, one level at a time. Each level:
   - takes its own slice of distinct inputs;
   - starts from a row restarted since its last cell, and refuses to start unless the row's
     multimodal and prefix cache query counters read 0;
   - writes one result.

   The runner refuses a missing or malformed argument before its first request. A shell test, run
   by the check, covers its arguments and refusals.
7. The bench has an agent capacity scenario, ported from spike-model-layout. `levels.jq` gains an
   agent purpose that reports the ITL median, the TTFT median, and output tokens a second. The
   bench lint and tests cover it.
8. Measure on one host takes the host's last survey through up to three passes, each on one
   state:
   - **An engine move:** the candidate vLLM release runs from a branch with the pin moved. The
     host's clone checks out that branch before `hosting engine update`. Rollback is the default
     branch and the same update.
   - **A settings check:** one row is measured with and without a profile change, set from a
     branch.
   - **A candidate screen:** the card, the policy gates, probes, a capacity cell, and accuracy.
     An agent candidate stops at "needs `model-evaluation`'s tiers".

   Every load goes through the bench cell runner. Measure records its cells in that purpose's
   findings, with each command as it ran. It prints each command that changes the host before it
   runs it.
9. The verdict. An engine move is adopted only when every row passes two tests:
   - **Accuracy holds:** full transcripts of the audio probe clips; embedding nDCG@10 within 0.02
     on its subsets; the vision probes' prompt tokens unchanged; and the agent ITL floor met at
     its target.
   - **Throughput holds:** the row's throughput peak is within its run noise of the incumbent's,
     or ahead.

   Otherwise the move is held, with a finding. The pin moves only when all four hosts hold. The
   architect may overrule, and the record gives the reason. A settings check and a candidate
   screen use the same rule for their one row.
10. The skill lives in the repository's `.claude/` and has three modes: `setup`, `survey <host>`,
    and `measure <host>`. It reads its inputs from the docs above.
    - `setup` prints the permission rules each mode needs, marks each present or missing, and
      writes no settings.
    - With no host given, the skill lists the descriptors and asks which host to use.
11. Live runs:
    - Survey runs live and read-only on gb10-1, gb10-2, framework, and framework-2, and each
      report is read for coherence.
    - Measure prints its full pass for one host and runs none of it: no row is restarted,
      updated, or loaded.
12. ai-hosting's context names upgrade evaluation as built. Its notes resolve what they left to
    this task: the name of the stale verb, the off-pin rehearsal, and the gfx1151 watch.

    The goal record gains this task's Decisions and its pending edits to the coordinator. One of
    those edits reconciles the coordinator's two statements on host state: reports stay
    untracked, and measurements are findings.

**Test seams**
- `mise run check`: shellcheck, links, the bench lint, `hosting profile validate`, and the shell
  tests for `hosting profile stale`, the cell runner, and `levels.jq`'s agent purpose.
- `mise run currency` and `mise run watch`.
- The skill's three modes, run live in behavior 11.

**Slices**
1. Upgrade ai-hosting: marathon 0.24.1, uv 0.13.10, and otel-collector-contrib 0.166.0. Python
   stays held. Done when currency reports only held items and the check passes.
2. Bench: the cell runner and its test, the agent scenario, and `levels.jq`'s agent purpose. The
   bench docs call the runner. The check passes.
3. Suite and watch: `hosting profile stale` and its test, and the gfx1151 entry in the watch
   register. The check and watch pass.
4. Documents: the convention, the policy, and the four host descriptors. The check passes.
5. The skill: setup, survey, and measure, with the probe. `setup` runs clean.
6. Live runs and records: the four surveys and the printed measure pass. Then the context, the
   notes, the Decisions, and the pending edits. Then the standards, spec, and editor passes over
   the whole diff.

**Out of scope**

- Any live load, restart, or engine move.
- Moving the pin or any `measured_vllm`; `acceptance` re-measures every row on v0.34.0.
- The BFCL and conform agent tiers, which stay with `model-evaluation`.
- The plugin form, which is v1.harness's.
- The spike's research cache, its blocker register, and llama.cpp support.
- Run noise for any host but gb10-2.

**Door**

Two-way: one repository, no release. The live surveys reach all four hosts over SSH, read-only.

## Decisions

- plan: The `architecture` overlap with v1.ai.processing and harness.optimization stays, as the
  intake accepted (PR #174 decision 2).
- secrets, plan (round 1): fnox enrolls the laptop and gb10-2, gb10-2 in ai-hosting alone.
  Enrolling gb10-1, the Framework, and framework-2 is dropped: none runs a secret-using task.
- hosts plan: Shell tests are plain-bash scripts run by the check; bats-core rejected: it adds a
  tool, and claude-plugins' plain-bash tests are the workspace precedent.
- migrate plan: the laptop's `~/experiments` clones stay. "Workstation" means the hosts (four, with framework-2).
- embedding plan: architecture never names the embedding model, the layout, or its rate.
- embedding (architect, at BRIEF): Embeddings have no cloud fallback; they route only to
  self-hosted rows. Rejected: e5 on Foundry managed compute (always on, about $384 a month, no
  scale to zero) and a closed serverless model (OpenAI, Cohere: different vectors, documents leave
  the premises).
- embedding plan: if e5 must be replaced, EmbeddingGemma 2 is the next candidate, if vLLM v0.34.0
  serves it. Rejected (framework-2, round R1): multilingual-e5-large-instruct, a variant of e5;
  the fallback is a distinct model.
- framework-2 plan (architect, round 2): no model of Chinese origin is admitted unless cleared
  (upgrades, escalation 3), and a fine-tune takes its base's origin; this replaces
  `ai-strategy.md`'s "only when no alternative serves".
- framework-2 (escalation 2): one port per alias stays; rejected every row on 8000 (no two rows
  could share a host).
- gateway plan (architect, round 1): the off-LAN path is removed from the goal: no peer relay, no
  relay-sized client timeouts, and no off-LAN cells. Rejected: keeping it in `gateway`, a `remote`
  task, or a backlog entry. This supersedes framework-2 (escalation 4)'s off-LAN line.
- gateway (escalation 2): `acceptance` proves bulk priority 10 and the 600 and 1,200 a-minute
  chat buckets live, with the bulk key it issues.
- vision-image-tokens (architect, redirect): the vision row's image budget is set for accuracy
  first, 1120 soft tokens, Gemma 4's largest; its cap is its throughput peak, images processed over
  time, not the most streams under a 10 s latency median; a request's latency only sizes client
  timeouts.
- vision-image-tokens (architect, at BRIEF): the same rule tunes the audio row as a general audio
  endpoint, and clients shape their requests to what the row proves. Its cap is its throughput
  peak on 30 s windows, the heaviest request it transcribes whole; RTFx is reported, not a floor.
- vision-image-tokens: Gemma 4 E4B transcribes at most 30 s of a clip, no setting raises it, and
  vLLM cuts a longer clip without an error. Clients window their audio; the report to
  v1.ai.inference gives the limit.
- vision-image-tokens: `acceptance` re-measures the vision row at 1120 in the standing layout cell
  with docinfer's dense pages, whose replies run to about 2,048 tokens against the bench's 100, and
  resets its cap and queue limit to that run's throughput peak. It moves `measured_vllm` to v0.34.0
  once it re-measures the fraction there; until then v0.33.0 stays, since `fraction_reason` rests on
  the spike's v0.33.0 E.1 cell.
- vision-image-tokens: `acceptance` re-measures the audio row with real windows from docinfer, as
  it does the vision row.
- plan (architect, round 2): no `budgets` task. Cloud spend is governed in Azure, deployment
  capacity as the rate ceiling and a Cost Management budget alert; `acceptance` removes the
  gateway's per-key token budgets. This replaces vision-image-tokens' `budgets` task and the bulk
  1,000,000-token Block. Rejected: per-key USD budgets in agentgateway (more to maintain, and a
  spent Block key is refused on the self-hosted rows too) and token counting per backend (needs a
  rate-limit service).
- plan (architect, round 1): `acceptance` works in go-ai and docinfer and fixes there, waiting on
  v1.ai.inference's lock. The Azure deployments change by az CLI, recorded in `docs/gateway.md`.
- upgrades plan (round 1): `acceptance` runs its load cells through the bench cell runner,
  `bench/cell.sh`, the agent scenario included.
- upgrades (escalation 2): the quantization floor is replaced by measurement on the target host:
  accuracy and capability first, then throughput at the row's cap and queue limit. A card's evals
  only rank candidates. Rejected (escalation 1): a hard 1% ceiling on a card's evals against BF16.
- upgrades (escalation 3): the origin rule keeps a clearance exception, which the architect
  admits: a release NIST's CAISSI (formerly CAISI) or UK AISI evaluated, that exact release, with
  covert behavior or backdoors and agent hijacking assessed, and parity with its U.S. references.
  The intent is a path for Chinese models far more capable than other open weights. Rejected: the
  spike's adversarial-entity list.
- upgrades (escalation 4): a generator of a candidate's training targets is a teacher; a model
  that only filtered, labeled, punctuated, or cleaned human data is not.
- upgrades (escalation 4, architect): survey reads CAISSI, UK AISI, and backdoor-detection work
  each run, and proposes policy changes from it.
- upgrades: `acceptance` commits the vision probe's inputs and command, the probe-1120 pages.
  Until then no vision measure pass reaches a verdict.
- upgrades: `acceptance` sets each host's run noise by repeating the incumbent's peak level.
  gb10-2's figure is from llama.cpp's anchors, not vLLM.
- upgrades: `bench/cell.sh` checks the cache counters once per cell, before its first level, not
  before every level, so a row needs a restart between cells, not between levels.

- upgrades (architect, at BRIEF): the current models stay at least until the capstone completes;
  the candidates the surveys proposed (gb10-2's Gemma 4 31B QAT and NVFP4 and Muse Glimmer 30B
  NVFP4, framework's Gemma 4 12B) are not screened before then.
