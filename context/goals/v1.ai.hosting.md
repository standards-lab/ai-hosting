## Task brief · acceptance

**Problem**

The rows were tuned one at a time, on synthetic inputs. Agent and vision still rest on v0.33.0
measurements. Vision's cap comes from 100-token replies, where real pages reply with up to 2,048
tokens, and audio's from LibriSpeech windows, with no level above 32. No host has run noise
measured on vLLM, and the four rows haven't run together since the spike. Bulk priority and the
chat buckets are unproven live, the gateway still charges per-key budgets, the overflow
deployments sit at setup capacity, and nothing alerts on Azure spend. go-ai's and docinfer's tiers
have never run through the gateway. The capstone builds on all of this.

**Behaviors**
1. Inputs. A committed builder writes the bench's dense-page and real-window rows from the local
   docproc run, and a committed sha256 manifest checks them. Two redistributable CFR pages and the
   vision probe's command are committed, so a vision measure can reach a verdict. No input that is
   not redistributable is committed.
2. Agent on v0.34.0. The bench gains the spike's S-agent session scenario. The agent row is
   measured at 4 and 12 sessions, each level on its own. The KV cache and memory low-water are read
   at the row's start, and the long-session capacity scenario runs once. The profile's reasons
   cite the new cells, and `measured_vllm` reads v0.34.0.
3. Vision at 1120. In the standing layout cell, the vision row runs dense pages at 2, 4, and 8
   streams, 10 min a level. Its cap and queue limit are set to the throughput peak in images a
   minute. Its fraction is re-measured on v0.34.0 at a cold start, then `measured_vllm` reads
   v0.34.0.
4. Audio on real windows. docinfer's 30 s windows run at 8, 16, 24, 32, and 48 streams, 90 s a
   level, each level on its own, and the cap and queue limit are set at the throughput peak.
5. `hosting profile stale` lists no row.
6. The standing layout cell runs the four rows together: agent at its target, vision through
   behavior 3's levels, audio at its target, and embedding at a constant 78 req/s. Each row's
   figures are recorded against its row-alone cell, and the preliminary labels are resolved.
7. Run noise. On each of the four hosts, the incumbent's peak level is repeated once from a
   restarted row, and every host descriptor gives a spread measured on vLLM.
8. Every load cell runs through the bench cell runner. Each lands in its purpose's findings with
   its command as run, and the profile reasons cite it.
9. The bulk key. Consumer `ai-hosting`, class bulk, is issued into ai-hosting's fnox and kept.

10. The gateway charges no per-key token budget. Postgres keeps the request log. The unrouted Azure

11. Overflow capacities are sized to each row's measured peak, capped by quota: about 100 for

    The gateway doc records both, with the az commands as run.
12. An overflow cell for each of agent, vision, and audio. With the row container stopped, the
    alias's load target runs through the gateway for 90 s, stopping at Azure's first 429 or at 300

    alias's return to its row once the row is back.
13. A dense-page vision request through the gateway completes, its reply over 200 s included.

    - Embedding's tokenize route gets a bucket only if the cells measure a need, and the gateway
      doc says which.

16. ai-hosting's context names acceptance as built. The goal record gains this task's Decisions

load on the rows.

**Out of scope**

- Replacing or screening any model: the current models stay until the capstone.
- The BFCL and conform agent tiers, which stay with `model-evaluation`.
- A full docinfer run over the docproc run.
- Moving the vLLM pin.
- Any docproc change.
- Off-LAN paths.

**Door**

One-way: the deleted Azure deployment and any release tag. Two-way: everything else, the
capacities, budget, profiles, gateway config, and keys included.

**Release**

ai-hosting releases nothing. A tag is cut only for a module a fix lands in, following
v1.ai.inference's tags:

- go-ai: `v0.5.1`, then `tools/infer/v0.4.1` if infer changes or must require the fix.
- docinfer: `v0.3.1`, then `postgres/v0.1.2` and `cmd/docinfer/v0.2.1` where each changes or
  must require the fix.

Each tag sits on a commit that requires the released tags beneath it, go-ai before docinfer.

## Decisions

- plan: The `architecture` overlap with v1.ai.processing and harness.optimization stays, as the
  intake accepted (PR #174 decision 2).
- secrets, plan (round 1): fnox enrolls the laptop and gb10-2, gb10-2 in ai-hosting alone.
  Enrolling gb10-1, the Framework, and framework-2 is dropped: none runs a secret-using task.
- hosts plan: Shell tests are plain-bash scripts run by the check; bats-core rejected: it adds a
  tool, and claude-plugins' plain-bash tests are the workspace precedent.
- migrate plan: the laptop's `~/experiments` clones stay. "Workstation" means the hosts (four, with framework-2).
- embedding plan: architecture never names the embedding model, the layout, or its rate.
- embedding (architect, at BRIEF): Embeddings have no cloud fallback; they route only to
  self-hosted rows. Rejected: e5 on Foundry managed compute (always on, about $384 a month, no
  scale to zero) and a closed serverless model (OpenAI, Cohere: different vectors, documents leave
  the premises).
- embedding plan: if e5 must be replaced, EmbeddingGemma 2 is the next candidate, if vLLM v0.34.0
  serves it. Rejected (framework-2, round R1): multilingual-e5-large-instruct, a variant of e5;
  the fallback is a distinct model.
- framework-2 plan (architect, round 2): no model of Chinese origin is admitted unless cleared
  (upgrades, escalation 3), and a fine-tune takes its base's origin; this replaces
  `ai-strategy.md`'s "only when no alternative serves".
- framework-2 (escalation 2): one port per alias stays; rejected every row on 8000 (no two rows
  could share a host).
- gateway plan (architect, round 1): the off-LAN path is removed from the goal: no peer relay, no
  relay-sized client timeouts, and no off-LAN cells. Rejected: keeping it in `gateway`, a `remote`
  task, or a backlog entry. This supersedes framework-2 (escalation 4)'s off-LAN line.
- gateway (escalation 2): `acceptance` proves bulk priority 10 and the 600 and 1,200 a-minute
  chat buckets live, with the bulk key it issues.
- vision-image-tokens (architect, redirect): the vision row's image budget is set for accuracy
  first, 1120 soft tokens, Gemma 4's largest; its cap is its throughput peak, images processed over
  time, not the most streams under a 10 s latency median; a request's latency only sizes client
  timeouts.
- vision-image-tokens (architect, at BRIEF): the same rule tunes the audio row as a general audio
  endpoint, and clients shape their requests to what the row proves. Its cap is its throughput
  peak on 30 s windows, the heaviest request it transcribes whole; RTFx is reported, not a floor.
- vision-image-tokens: Gemma 4 E4B transcribes at most 30 s of a clip, no setting raises it, and
  vLLM cuts a longer clip without an error. Clients window their audio; the report to
  v1.ai.inference gives the limit.
- vision-image-tokens: `acceptance` re-measures the vision row at 1120 in the standing layout cell
  with docinfer's dense pages, whose replies run to about 2,048 tokens against the bench's 100, and
  resets its cap and queue limit to that run's throughput peak. It moves `measured_vllm` to v0.34.0
  once it re-measures the fraction there; until then v0.33.0 stays, since `fraction_reason` rests on
  the spike's v0.33.0 E.1 cell.
- vision-image-tokens: `acceptance` re-measures the audio row with real windows from docinfer, as
  it does the vision row.
- plan (architect, round 2): no `budgets` task. Cloud spend is governed in Azure, deployment
  capacity as the rate ceiling and a Cost Management budget alert; `acceptance` removes the
  gateway's per-key token budgets. This replaces vision-image-tokens' `budgets` task and the bulk
  1,000,000-token Block. Rejected: per-key USD budgets in agentgateway (more to maintain, and a
  spent Block key is refused on the self-hosted rows too) and token counting per backend (needs a
  rate-limit service).
- plan (architect, round 1): `acceptance` works in go-ai and docinfer and fixes there, waiting on
  v1.ai.inference's lock. The Azure deployments change by az CLI, recorded in `docs/gateway.md`.
- upgrades plan (round 1): `acceptance` runs its load cells through the bench cell runner,
  `bench/cell.sh`, the agent scenario included.
- upgrades (escalation 2): the quantization floor is replaced by measurement on the target host:
  accuracy and capability first, then throughput at the row's cap and queue limit. A card's evals
  only rank candidates. Rejected (escalation 1): a hard 1% ceiling on a card's evals against BF16.
- upgrades (escalation 3): the origin rule keeps a clearance exception, which the architect
  admits: a release NIST's CAISSI (formerly CAISI) or UK AISI evaluated, that exact release, with
  covert behavior or backdoors and agent hijacking assessed, and parity with its U.S. references.
  The intent is a path for Chinese models far more capable than other open weights. Rejected: the
  spike's adversarial-entity list.
- upgrades (escalation 4): a generator of a candidate's training targets is a teacher; a model
  that only filtered, labeled, punctuated, or cleaned human data is not.
- upgrades (escalation 4, architect): survey reads CAISSI, UK AISI, and backdoor-detection work
  each run, and proposes policy changes from it.
- upgrades: `acceptance` commits the vision probe's inputs and command, the probe-1120 pages.
  Until then no vision measure pass reaches a verdict.
- upgrades: `acceptance` sets each host's run noise by repeating the incumbent's peak level.
  gb10-2's figure is from llama.cpp's anchors, not vLLM.
- upgrades: `bench/cell.sh` checks the cache counters once per cell, before its first level, not
  before every level, so a row needs a restart between cells, not between levels.

- upgrades (architect, at BRIEF): the current models stay at least until the capstone completes;
  the candidates the surveys proposed (gb10-2's Gemma 4 31B QAT and NVFP4 and Muse Glimmer 30B
  NVFP4, framework's Gemma 4 12B) are not screened before then.
- acceptance plan (round 1): the bulk key is kept, consumer `ai-hosting` in ai-hosting's fnox,
  for later priority checks and upgrade measures.
- acceptance plan (round 1): a fix `acceptance` lands in go-ai or docinfer is released as a patch
  tag at SHIP, since the capstone consumes tags; ai-hosting releases nothing.
- acceptance plan (round 2): docinfer's docproc is not held; v1.ai.inference brings it to v0.8.0,
  and the upgrade slices take whatever trails at build.
- acceptance plan (start, round 1): go-ai and docinfer were current at approval, so one upgrade
  slice, ai-hosting's, replaced their two and rechecks all three at build.
