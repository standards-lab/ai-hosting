## Task brief · architecture

**Problem**

The goal ends with what it learned held only in spike repositories about to be archived and in
ai-hosting. The parts that hold beyond one repository, reading a model card and making tool calls
reliable, need architecture pages that the repositories' standards point to. Sizing a row and
placing rows hold only in ai-hosting, which doesn't yet state the placement rule. ai-hosting's
notes still read as if later tasks remain, and the sync needs a complete, accurate set of pending
edits, including the archive of the repositories ai-hosting replaced.

**Behaviors**
1. architecture holds a principle page on reading a model card for a served checkpoint: what each
   value means (sampling, reasoning control, chat template, context ceiling, stop tokens,
   multi-turn rules, prompt forms); that the card, not a conversion or an engine's defaults, is the
   source; that only a checkpoint derived from another publisher's model takes sampling from that
   base card, and only when its own generation config lacks it; and that a card's evals only rank
   candidates, which measurement on the target host judges. It names no embedding model, layout,
   or rate, and asserts no repository's current state.
2. architecture holds a principle page on tool-call reliability with three layers: the server
   constrains a shape the consumer needs every time; a row runs the model's official chat template
   at the card's settings; the client sends reasoning back on turns that called tools. It names no
   repository's current behavior as fact.
3. Both pages carry principle front matter, are listed in architecture's principles index, and
   architecture's check passes.
4. ai-hosting's, go-ai's, and docinfer's STANDARDS.md each point to the pages that apply to them,
   one line each, and each repository's check passes.
5. ai-hosting's docs state the placement rule with its evidence, and its sizing rule stays its
   own. Its notes close what remained open for later tasks: the spike-model-hosting note reads as
   what was taken, and the gfx1151 MIOpen upstream report is left to the watch register, not the
   backlog.
6. The goal record's pending edits are complete for the sync: the coordinator's ai-hosting doc
   drops its per-task sections and moves what stays open (FP8 KV calibration, streamed-video load,
   the network path, the gateway's unverified trace id and exemplars) to "Inputs for later goals",
   replacing the upgrades and acceptance "record it built" edits; the coordinator's ai-hosting note
   names the two pages and keeps sizing and placement in ai-hosting; the catalog marks the archived
   remotes; `[workspace.paths]` drops the archived spikes; personal-agents' README links forward to
   ai-hosting before its archive; and personal-agents, spike-model-engines, spike-model-gateway,
   and spike-hosting-upgrades are archived. The Decision on the architecture overlap is dropped.

## Decisions

- plan: The `architecture` overlap with v1.ai.processing and harness.optimization stays, as the
  intake accepted (PR #174 decision 2).
- secrets, plan (round 1): fnox enrolls the laptop and gb10-2, gb10-2 in ai-hosting alone.
  Enrolling gb10-1, the Framework, and framework-2 is dropped: none runs a secret-using task.
- hosts plan: Shell tests are plain-bash scripts run by the check; bats-core rejected: it adds a
  tool, and claude-plugins' plain-bash tests are the workspace precedent.
- migrate plan: the laptop's `~/experiments` clones stay. "Workstation" means the hosts (four,
  with framework-2).
- embedding plan: architecture never names the embedding model, the layout, or its rate.
- embedding (architect, at BRIEF): Embeddings have no cloud fallback; they route only to
  self-hosted rows. Rejected: e5 on Foundry managed compute (always on, about $384 a month, no
  scale to zero) and a closed serverless model (OpenAI, Cohere: different vectors, documents leave
  the premises).
- embedding plan: if e5 must be replaced, EmbeddingGemma 2 is the next candidate, if vLLM v0.34.0
  serves it. Rejected (framework-2, round R1): multilingual-e5-large-instruct, a variant of e5;
  the fallback is a distinct model.
- framework-2 plan (architect, round 2): no model of Chinese origin is admitted unless cleared
  (upgrades, escalation 3), and a fine-tune takes its base's origin; this replaces
  `ai-strategy.md`'s "only when no alternative serves".
- framework-2 (escalation 2): one port per alias stays; rejected every row on 8000 (no two rows
  could share a host).
- gateway plan (architect, round 1): the off-LAN path is removed from the goal: no peer relay, no
  relay-sized client timeouts, and no off-LAN cells. Rejected: keeping it in `gateway`, a `remote`
  task, or a backlog entry. This supersedes framework-2 (escalation 4)'s off-LAN line.
- upgrades (escalation 2): the quantization floor is replaced by measurement on the target host:
  accuracy and capability first, then throughput at the row's cap and queue limit. A card's evals
  only rank candidates. Rejected (escalation 1): a hard 1% ceiling on a card's evals against BF16.
- upgrades (escalation 3): the origin rule keeps a clearance exception, which the architect
  admits: a release NIST's CAISSI (formerly CAISI) or UK AISI evaluated, that exact release, with
  covert behavior or backdoors and agent hijacking assessed, and parity with its U.S. references.
  The intent is a path for Chinese models far more capable than other open weights. Rejected: the
  spike's adversarial-entity list.
- upgrades (escalation 4): a generator of a candidate's training targets is a teacher; a model
  that only filtered, labeled, punctuated, or cleaned human data is not.
- upgrades (escalation 4, architect): survey reads CAISSI, UK AISI, and backdoor-detection work
  each run, and proposes policy changes from it.
- upgrades (architect, at BRIEF): the current models stay at least until the capstone completes;
  the candidates the surveys proposed (gb10-2's Gemma 4 31B QAT and NVFP4 and Muse Glimmer 30B
  NVFP4, framework's Gemma 4 12B) are not screened before then.
- acceptance (escalation 1): a row's cap is a throughput peak found by running levels until the
  rate stops rising, past a brief's top level if need be; vision and audio ran past theirs.
- acceptance (escalation 2): vision has no throughput peak within the KV cache that holds
  full-context requests, so its cap is 32, with the fraction raised to 0.55 so the cache holds
  32 × 8,192, audio's rule. Rejected: cap 16 at fraction 0.40, and keeping cap 8.
- acceptance (escalations 3, 4): vLLM v0.34.0's `--max-num-queued-reqs` counts running plus
  waiting requests. The queue limits stay at vision 64 (32 waiting, so the last finishes inside a
  client's 600 s), audio 192, and agent 24. Rejected: each raised to its cap plus the waiting
  count (vision's 96 would wait near 580 s).
- acceptance (escalation 4): the gateway rewrites requests for the Azure backends, dropping or
  renaming the fields each deployment refuses, so a client addresses an alias without knowing
  its backend. Rejected: clients omitting the fields.
- acceptance (escalation 5): vision's overflow sets `reasoning_effort: "minimal"` on gpt-5-mini,
  so a client's token bound stays a bound on text. Rejected: raising the bound.
- acceptance (architect): embedding stays at cap 16; a cap-4 cell is not run.
- acceptance (architect): the capstone tunes each client's concurrency per alias live, against
  the row caps and findings; a row's cap bounds only the worst case.
- acceptance: priority scheduling orders only vLLM's waiting queue; a running bulk request is not
  preempted.
- acceptance: a cap for long requests is read on a level's second-half rate, which leaves out the
  level's ramp and the requests still in flight at its end.
- acceptance: an overflow cell's stop point, Azure's first 429 or its 300th request, is read from
  the gateway's request log, since GuideLLM can't stop on a status code.

- architecture plan (round 1): sizing a vLLM row and the placement rule stay in ai-hosting; only
  the model-card and tool-call reliability pages go to architecture, in `principles/`. The
  reliability page states three layers (server constraint, card template and sampling, reasoning
  sent back); harness retry, gateway resampling, and pass^k stay in the archived spike.
- architecture plan (round 1): the gfx1151 MIOpen upstream report rides ai-hosting's watch
  register; no backlog entry.
