# gb10-2

This is the descriptor of the second GB10 workstation, which a survey and a measure read to reach
the host and judge what they find there ([the upgrade convention](../upgrades.md)). Every other fact
about the host comes from the probe a survey takes. The host also runs the gateway's compose stack
([the gateway](../gateway.md)).

## SSH short name

`gb10-2`

## Alias

`vision`, from the gb10 class's profile. The gateway's config is the home of which host serves
which alias ([config.template.yaml](../../compose/agentgateway/config.template.yaml)).

## Load target

The `vision` row's `[rows.load]` table in the [gb10 profile](../../classes/gb10/profile.toml).

## Run noise

Output tok/s, on llama.cpp's anchors A and B (`gpt-oss-120b` in MXFP4), not on the vision row on
vLLM, from spike-model-layout's parity cells of gb10-2 against gb10-1, each anchor run twice from
a fresh load (spike-model-layout `docs/findings/hosts.md`, "E. Parity: gb10-2 against gb10-1", at
`e64d9c4`; standards-lab `docs/ai-hosting.md`, "The `upgrades` task"):

- **Within-session**: 2.37% on anchor A, 0.52% on anchor B; the verdict reads the wider, 2.37%.
- **Across-days**: not measured.

A measure on vLLM replaces these with its own spread, by [the verdict](../upgrades.md#the-verdict).
